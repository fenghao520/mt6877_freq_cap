==============================================================
        天玑920限频（复刻若晴官调限频 v4.4）
        适用：Redmi Note 11 Pro+ / 天玑920 (mt6877)
==============================================================

【原作与移植说明】
  原作：ynltoto「若晴官调限频 v4.4」（面向 骁龙8至尊版 SM8750 / SM8850）
  本模块按同一功能模型移植到天玑920，核心差异如下：

  1. 控制通道不同（最关键）
     高通版：写 /sys/devices/system/cpu/cpufreq/policyX/scaling_max_freq
     天玑版：该节点会被 MTK PPM 引擎实时覆盖（实测写入后立刻弹回硬件最大值），
             必须改走 MTK 原生通道：
                 /proc/ppm/policy/cluster_0_max_freq   （A55 小核簇）
                 /proc/ppm/policy/cluster_1_max_freq   （A78 大核簇）
     该节点写入 kHz 值，内核自动对齐到真实 OPP 档位，因此不可能写入非法频点。
     ⚠️ 但**读回的值不是 kHz，而是「该簇 OPP 表的降序索引」**（v1.1.0 实测确认）：
          A55(cluster0) 索引 0..15 → 2000 1903 1800 1703 1600 1503 1407 1310
                                      1260 1150 1053 980 900 740 650 500 (MHz)
          A78(cluster1) 索引 0..15 → 2500 2400 2275 2150 2000 1900 1800 1660
                                      1540 1430 1300 1140 1040 910 740 650 (MHz)
        -1 仍表示「不限」。util.sh 的 ppm_khz() 负责换算，ctl.sh status 与 WebUI
        显示的都是换算后的 MHz，state.conf 里 c0_hz/c1_hz 是换算值、
        c0_now/c1_now 是原始索引（判断「是否已放开」用）。

  2. 「0」的含义不同（重大陷阱）
     高通版约定 0 = 硬件最大值。
     天玑这个通道上写 0 会被内核解释成最低档（实测 → idx15 = 650MHz），
     直接写 0 等于把 CPU 压到最低频，手机会卡到不可用。
     本模块已做防护：最终写入前 0 / 负数 / 非数字 一律转成 -1（不限）；
     只有 -1 才是真正的「不限」，卸载与恢复都写 -1。
     （配置层为保守起见：自定义频率填非数字=视为没配该项，回退档位表；
       想放开某一簇请显式写 0 或 -1。）

  3. 集群拓扑
     cluster0 = policy0 = 6×Cortex-A55 (cpu0-5)  500MHz ~ 2000MHz
     cluster1 = policy6 = 2×Cortex-A78 (cpu6-7)  650MHz ~ 2500MHz
     调度器保持官方 schedutil，本模块不改调度器、不改电压。

  4. 未移植的部分
     · 刷新率管理（骁龙版用 SurfaceFlinger service call 1035，天玑不适用）→ 不做
     · 智能校准学习（原闭源二进制实现）→ 不做
     · GPU 限频：本机的 /proc/gpufreq 只有开关式接口，无法安全设置任意上限 → 不做

--------------------------------------------------------------
【模块作用】
  只限制 CPU 最高频率，不改动官方调度，降低发热与功耗、提升续航。
  自动区分「日用 / 游戏」两套档位，熄屏自动解除限制。

【怎么用】
  推荐在 KernelSU 管理器点本模块的「打开 WebUI」（底部六个页签）：
    · 模式：实验功能开关（全部拉满，仅供跑分）+ 运行状态
            + 日用 / 游戏 各四档，点选 1~3 秒内生效
    · 频率：全局自定义频率（开关 + 四格选择器，点选即弹液态选择器）
            + 档位表（4 档 × 日用/游戏 × 小核/大核，点任意一格即可改该档上限）
    · 深睡：深度睡眠开关 + 白名单（加/移应用）+ 唤醒排行
    · 刷新率：按场景锁定刷新率（日用/游戏分开设），熄屏自动交还系统
    · 安全：立即恢复不限 / 停用·恢复限频 / 重启守护 / 停守护并恢复
    · 关于：原理、约定、致谢
  顶栏右上角可切「日间 / 夜间」主题。

  也可以命令行（adb 或任意终端）：
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh status
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh dryrun         # 只算不写
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh mode daily balance
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh restore        # 恢复不限
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh disable/enable
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh ds on|off|status
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh ds enter|exit  # 立即进入/还原
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh dswhite list
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh dswhite add com.tencent.mm
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh rr status      # 刷新率状态
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh rr on|off
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh rr daily 60    # 日用锁 60Hz
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh hyper status   # 实验功能状态/能力
    sh /data/adb/modules/mt6877_freq_cap/scripts/ctl.sh hyper on|off   # 全部拉满 / 恢复

  执行按钮（无 WebUI 时）：音量+ 切档（先选日用/游戏，再选档位），音量- 卸载并恢复。

【行为细节】
  · 开机提速：系统开机后约 100 秒内（/proc/uptime < 100）按「极速」满血运行，
    避免开机卡顿，之后自动恢复你的设置。注意判定依据是系统开机时长，
    所以 WebUI 点「重启守护」或覆盖更新模块都不会触发提速。
  · 熄屏解锁：熄屏即把两簇写回 -1，完全交还系统调度；亮屏重新限频
  · 游戏识别：按包名名单（config/games.list 316 个），与横竖屏无关
  · 热重载：改配置文件后 3 秒内自动生效，不用重启
  · 「立即恢复不限」：两簇写回 -1 后**保持放开**（守护继续运行但不再限频），
    点任一档位按钮或切到游戏场景即重新接管；想要持久停用请点「停用限频」
  · 「重启守护」：只重启守护进程，不触发开机提速、不改频率设置
  · 优先级：全局自定义 > 档位表覆盖(tier_freq.conf) > 内置预设表 > 硬件最大值

【配置文件】/sdcard/Android/mt6877_freq_cap/
  mode.conf          mode_daily / mode_game（当前场景所选档位）
  custom_freq.conf   ENABLE=1 后填 LITTLE/BIG × DAILY/GAME（kHz）
                     0 / -1 = 该簇不限；留空或非数字 = 视为没配，回退档位表
  tier_freq.conf     档位表覆盖（WebUI「频率 → 档位表」写入）
                     键名必须全大写 <档位>_<LITTLE|BIG>_<DAILY|GAME>，缺省项用内置预设
                     （守护查表时会统一转大写，因此小写键名也能识别）
  mygames.list       自己补的游戏包名，一行一个
  dsleep.conf        深度睡眠（WebUI「深睡」页写入）
                     enable=0/1 · whitelist=包名,包名 · grace=熄屏宽限秒（默认 20）
  ds/                深睡运行目录（active/saved.conf/alarm.base/wake.tsv），自动维护
  rrate.conf         刷新率管理（WebUI「刷新率」页写入）
                     enable=0/1 · daily=Hz · game=Hz
  rrate.saved        刷新率原值快照（min/peak），用于还原；无它则不动系统设置
  rrate.held         存在 = 当前正被模块锁着，内容是锁定的 Hz
  hyper.conf         实验功能（WebUI 首页开关写入）enable=0/1
  hyper.saved        实验功能原值快照（CPU 下限 / GPU / DDR），用于还原
  hyper.on           存在 = 处于满血状态；内容是未完成项清单
  使用说明.txt       本文件

【深度睡眠】（v1.2.0 新增，逻辑复刻自若晴 v4.4）
  怎么触发：熄屏 && 未充电 && 未放音，且持续 grace 秒（默认 20 秒）→ 自动进入
  进入时做的事（接管系统 Doze）：
    ① 白名单里的应用 → 加入系统 Doze 白名单（熄屏后照常工作）
    ② 其余「用户级」白名单应用 → 移出（强迫它们一起进 Doze）
    ③ 写入更短的 device_idle_constants（把进入深度空闲的等待从分钟级压到秒级）
    ④ cmd deviceidle force-idle → 直接强制进入 deep idle
  什么时候还原：亮屏 / 插上充电器 / 开始放音 / 关闭深睡开关 / 停守护 / 卸载模块
                / 重新开机（service.sh 会照快照补还原）
  还原方式：白名单逐项比对回滚（自己加进去的移除、自己移出去的加回），
            device_idle_constants 回到原值（原本是 null 就删掉该项）

  不会影响的东西：
    · 系统自带的 system / system-excidle 白名单（来电、短信、闹钟、IMS…）一律不动
    · 白名单（含默认的微信、QQ）在深睡期间照常工作
    · 充电中、正在放音时不会进入
  唤醒排行：以 dumpsys alarm 的 Alarm Stats 逐包做差，统计「上一次深睡期间」的活跃度。
            分两个口径：wakes（闹钟真正唤醒了设备）与 alarms（闹钟被触发）。
            优先用 wakes 排名 —— 那才是真的把手机叫醒的次数；如果整段深睡
            wakes 全为 0（说明深睡很干净，闹钟都在设备本已清醒时批处理掉了），
            就回退用 alarms 排名，保证榜单不会永远空白。WebUI 会标明当前口径。

  注意：settings 里的 device_idle_constants 与 Doze 白名单是**持久化**数据，
  所以模块在任何中断场景下都会补还原（uninstall / service.sh 开机清理），
  不会出现「卸载后系统一直过度休眠」。这也意味着深睡期间那条常量在
  「重启后的第一次开机」会是原值 —— 这是预期行为。

  ⚠ 别和系统自带的「省电模式 / 极致省电」叠加太久：两者都压后台，
    同时开会把消息推送也压住。要收微信就把微信加进白名单。

【安全设计 & 恢复方案】
  · 本模块只在开机后写 runtime 的 /proc 节点，不碰 boot / vendor 分区，
    —— 重启即清空全部限制，结构上不存在「刷入后无法开机」的可能。
  · 所有写入值先做数字校验，再钳制到 [cpuinfo_min_freq, cpuinfo_max_freq]，
    最后交给内核对齐到真实 OPP；最终写入前非数字 / 0 / 负数 一律转成 -1（不限）。
  · 守护进程启动失败时，service.sh 会自动把两簇恢复为 -1，不会留下半吊子限制。

  恢复四招（任选）：
    ① 运行时：WebUI 点「立即恢复不限」或「停用限频」；
       也可在 /sdcard/Android/mt6877_freq_cap/ 建一个名为 disable 的空文件。
    ② ADB：
       adb shell su -c "echo -1 > /proc/ppm/policy/cluster_0_max_freq; echo -1 > /proc/ppm/policy/cluster_1_max_freq"
    ③ 模块级：KernelSU 管理器移除本模块并重启（uninstall.sh 自动写回 -1）。
    ④ 全局级：创建 /data/adb/modules/.disable_modules 后重启 → 禁用所有模块。

【常见问题】
  Q：会和别的调度/调速模块冲突吗？
  A：会。请勿与其它调度调速工具同时使用（包括 asoul_affinity_opt 这类改调度的）。
     本模块只在官方 schedutil 之上管上限，叠加别人的调速会互相打架。
  Q：限频后卡顿？
  A：把该场景档位调高一档；自定义里把对应值调到接近硬件最大值即可。
  Q：卸载后有残留吗？
  A：走 KernelSU 管理器卸载 → 干净，实测逐项核对过：
       · 两簇上限写回 -1、守护进程归零、模块目录与 modules_update 副本一并删除；
       · 深睡若正激活，Doze 白名单与 device_idle_constants 会照快照逐条还原
         （29 条白名单全量比对 100% 一致，constants 回到 null）；
       · 唯一保留的是 /sdcard/Android/mt6877_freq_cap/ 下的 5 个文件
         （mode.conf / custom_freq.conf / tier_freq.conf / dsleep.conf / 使用说明.txt）
         —— 有意保留的纯文本配置，重装可直接沿用。
     想连配置一起清干净：
       rm -rf /sdcard/Android/mt6877_freq_cap
     ⚠ 切勿绕过卸载脚本（例如在文件管理器里直接删 /data/adb/modules/mt6877_freq_cap）：
       已运行的守护进程不会自己退出，会继续把频率压在旧上限；
       深睡若正激活，缩短的 device_idle_constants 与 force-idle 会留在系统里，
       而模块目录已消失、开机也没人补还原。补救三板斧后重启一次：
         su -c "echo -1 > /proc/ppm/policy/cluster_0_max_freq; echo -1 > /proc/ppm/policy/cluster_1_max_freq"
         su -c "settings delete global device_idle_constants"
         su -c "cmd deviceidle unforce"
  Q：没生效？
  A：先 ctl.sh status 看守护是否运行、前台是否被识别；再 ctl.sh dryrun 看算出来的值。

【v1.2.6 变更】（本版）
  修三项清理与快照缺陷（实机验证通过）：
  1. 熄屏交还满血：实验功能开启时，熄屏会一并释放 CPU 下限、GPU 固定、DDR 锁定。
     此前只放开 CPU 上限，GPU/DDR 仍在生效，待机功耗与发热下不来。
  2. ctl.sh stop 清理完整：改为先让守护优雅处理再兜底清理，
     与 WebUI 停止路径一致；深睡 Doze、刷新率、GPU/DDR 不再残留。
  3. 快照写失败不再改系统设置：min/peak_refresh_rate 等持久化设置的快照失败时
     直接拒绝接管并报错（WebUI 红字提示），不再出现「改了却无法还原」。
  限频与深睡的核心逻辑未改动。

【v1.2.5 变更】
  1. 新增「实验功能」（WebUI 首页开关，默认关闭）
     开启后立刻全局生效并覆盖日用/游戏模式：CPU 两簇上下限贴死、
     GPU 锁到 OPP 最高档、DDR 锁到最高档；关闭立即恢复。
     ⚠️ 仅供跑分使用 —— 功耗与发热显著上升，长时间用建议配外部散热器，
        玩游戏前请先关闭。
     节点：CPU 走本模块自己的 PPM 通道；GPU/DDR 走 MTK 通用接口
        （gpufreqv2/fix_target_opp_index、helio-dvfsrc/dvfsrc_force_vcore_dvfs_opp）。
        本机是否支持由守护开机探测后上报，不支持的会在开关下方标「本机无」。
     这些节点都是内核运行时状态，**重启一定清零**；停用/卸载/开机仍会照快照尝试还原。
  2. 实验功能带**自愈**：这几个内核值不是本模块独占，别的组件也能改。守护每轮复查
     （CPU 每 3 秒、GPU/DDR 约每 15 秒），发现被改回去就立刻写回；
     开关下方显示「已自动修复 N 次」，正常应恒为 0 —— 不是 0 说明有别的组件在抢。
  3. **UI 点击即时切换**：档位胶囊 / 开关 / 白名单增删 / 停用·恢复按钮改为乐观更新 ——
     点击后先改本地状态并立即重绘，再下发命令，失败回滚。
     （原来要等守护写 state.conf 再叠一次刷新，实测有 3~5 秒延迟，像「点了没反应」。）
  4. 顺带修两处隐患：ppm_release 在节点不存在时重定向失败会返回非 0
     （在 set -e 下会让脚本静默退出）；hy_detect 探测函数不应传出失败码。
  5. 限频与深睡的核心逻辑未改动。
  CLI: sh ctl.sh hyper on|off|status

【v1.2.3 变更】
  第二轮审计，专治「改了不生效 / 生效慢」。限频主逻辑仍未改动。
  1. 修复「写失败被当成成功，从此再也不补写」（本版最严重）：
     ppm_set 原本无条件 return 0，守护「写完就记签名、值没变就不重写」——
     于是偶发的一次写入失败会被永久记住，表现为改了档位完全不生效且不会自愈。
     现改为：写失败返回非 0，两簇都成功才记签名，否则下一轮重试。
  2. 修复改配置时频率会瞬间跳一下：WebUI 写 tier_freq.conf / custom_freq.conf
     用的是 cat > 目标（先截断成 0 字节），而守护每 3 秒读一次 —— 撞上窗口就
     读到空文件、回退预设。已全部改为 .tmp + mv 原子替换（mode.conf、dsleep.conf 同理）。
  3. 修复深睡宽限期内「点了没反应」：ds_off_tick 原先在 while 里 sleep 到宽限期满
     （最长 20 秒），这段时间主循环不转、命令全被压着。已改成非阻塞状态机。
  4. 修复场景切换慢一拍：FG_TTL=4 大于巡检间隔 3 秒，前台实际每两轮才识别一次。
     已改为 2 秒，保证每轮都扫。
  5. 修复按键操作改了游戏档却按日用档应用：action.sh 最后写死 apply_once.sh daily。
  6. 守护写 state.conf 前补一次 mkdir，避免配置目录被删后一直显示「未运行」。

【v1.2.2 变更】
  一次完整的代码审计，修掉 10 处问题。限频主逻辑一行未改。
  1. 修复「停用后深睡不还原」（本版最严重）：守护的停用分支排在屏幕判断之前，
     而 ds_on_tick / ds_off_tick 都在后面 —— 深睡中按下停用会让 force-idle 与
     缩短过的 device_idle_constants 永久留在系统里，连亮屏都不还原，
     而且设置里显示「已停用」，用户无从判断是谁干的。
  2. 修复「无快照时误删用户的 device_idle_constants」：ds_exit 原本无论有没有
     接管快照都会执行 settings delete，一旦被误调用就会永久抹掉用户自己的 Doze 常量，
     与 ds_cleanup 承诺的「没有证据不动它」自相矛盾。
  3. 修复「末尾无换行的命令被丢弃」：while read 对「最后一行没有换行符」
     会返回非零并跳过该行，表现为命令完全没生效。
  4. 修复命令文件读取竞态：原来「读完 → 处理 → 最后才清空」，中间追加的命令
     会被静默丢掉。改为先快照、立刻清空、再处理。
  5. 修复 ds_conf_set 并非原子写：注释声称原子替换，实际是 cat tmp > 目标
     （目标先被截断成 0 字节），WebUI 恰好读到会拿到空配置。已改为 mv。
  6. 修复 kill_daemon 可能杀错进程：/proc/PID/stat 的第 2 字段 (comm) 可能含空格，
     按空格切字段会让后面全部错位。实测本机 767 个进程里有 2 个触发。
  7. 堵住 get_tier 的任意代码执行面：预设表原本是 source "$PRESETDIR/$soc.conf" + eval，
     而 soc 来自 config/soc.override 的文件内容且未过滤 —— 写 ../.. 就能让模块
     以 root 执行预设目录之外的任意文件。现收敛 soc 到 [A-Za-z0-9_] 并改用 awk 解析。
  8. is_game 加 -F：原来包名里的 "." 被当正则通配，com.foo.bar 能命中 comXfooXbar。
  9. 新增 _is_int() 严格数字校验：原来 "-" / "1-2" / "--" 会被判成合法数字写进 /proc。
 10. action.sh 补上 MODDIR 修复（上一版改了其余 5 个入口，漏了这个）。
 11. 深睡期间的放音检测从每 3 秒改为每 15 秒：dumpsys media_session 太贵，
     光检测就吃掉省下来的电，与这个功能的目的背道而驰。
 12. WebUI 指令下发增加字符白名单，堵住 shell 注入面（指令最终拼进 echo '...'）。

【v1.2.1 变更】
  1. 修复卸载路径依赖：uninstall.sh / service.sh / daemon.sh / ctl.sh / apply_once.sh
     原先用 ${0%/*} 或 dirname "$0"/.. 解析自身目录，当脚本被以「不带斜杠的相对路径」
     调用时（例如 cd 到目录后执行 sh uninstall.sh）会算错，导致 util.sh 加载失败、

     可能恰好判定熄屏并重新接管 Doze，把刚做好的还原覆盖掉。
  3. ds_cleanup 在「无接管痕迹」时也会解除 force-idle（不再只依赖快照文件存在）。
     依旧不碰 device_idle_constants —— 用户自己设过的值，没证据就不能动。
  4. 卸载时一并清理 daemon.pid。
  5. README 补充卸载残留的实测结论，以及绕过卸载脚本的补救办法。
  6. 限频逻辑与深睡判定逻辑一行未改。
